# dsgners-agents — ИИ-команда dsgners

Четыре агента: графический дизайнер, веб-дизайнер, SMM-щик, SEO-шник. Работают на VPS, задачи и согласование — через Telegram-бота.

```
team/            общий мозг: бренд, правила, дизайн-система — читают все агенты
agents/designer     графический дизайнер: шаблоны визуалов HTML→PNG с автопроверкой
agents/webdesigner  веб-дизайнер: макеты блоков/страниц (HTML→PNG, 1440/390) + ТЗ
agents/smm          SMM-щик: посты в Telegram, визуалы просит у дизайнера, публикует после «Ок»
agents/seo          SEO-шник: проверка сайта и страниц, отчёты, ТЗ на правки
  у каждого: ROLE.md, checklist.md, feedback.md, tools.py, skills/
core/seo/        SEO-мониторинг сайта по расписанию (без ИИ) + автозадачи SEO-агенту
docs/            ТЗ для разработки сайта (seo-site-template.md — SEO в шаблоне статьи и списков)
core/            движок агентов, рендер HTML→PNG с автопроверкой, учёт расходов, правила из правок
bot.py           главный процесс: Telegram-бот + ИИ-офис
web/office.html  ИИ-офис: сцена, лента, история задач, знания агента, задачи
core/web.py      API офиса; core/runner.py — запуск задач; core/knowledge.py — знания
deploy/          установка и обновление на сервере
```

## ИИ-офис
Ссылка выдаётся в конце установки и по команде `/office` в боте. Вкладки у агента:
- **Лента** — что делает прямо сейчас, по шагам;
- **История** — все задачи с картинками, «Принять / Переделать», цепочки переделок;
- **Знания** — роль, чек-лист, правила (правятся прямо там), референсы «хорошо/плохо», документы .md/.txt/.pdf;
- **Навыки** — SKILL.md как у Claude: создать, загрузить (.md / .zip), править, включать/выключать.

Агенты работают командой: SMM, SEO и веб-дизайнер поручают задачи коллегам (`ask_colleague`),
результат коллеги прикладывается к их работе. В Telegram: просто текст — дизайнеру, `/web`, `/smm`, `/seo` — остальным.

Правки из офиса хранятся в `data/` на сервере и главнее версий из репозитория.

## SEO-мониторинг
Работает внутри бота, сам по расписанию (время московское):

| Когда | Что проверяет |
|---|---|
| каждый час | сайт отвечает, robots.txt не закрыл сайт и не поменялся молча, SSL не истекает |
| каждые 30 мин | новые и изменённые адреса в sitemap: проверка страницы, переобход в Яндексе, IndexNow; новые статьи → SEO-агенту на оформление |
| каждый день 08:30 | Вебмастер (страниц в поиске, критичные проблемы), Метрика (поисковый трафик вчера к прошлой неделе) |
| понедельник 09:00 | полный обход сайта → отчёт (ошибки, дубли title/description, битые ссылки, сироты, запросы на 4–15 местах, просевшие страницы) → SEO-агент делает список задач по приоритету |

| вторник 10:00 | контент-план: запросы Вебмастера (4–30 место, «показы без кликов»), просевшие статьи из Метрики, спрос из Вордстата без нашей страницы, прошлые темы → SEO-шник проверяет конкурентов и тренды и присылает N тем с обоснованием цифрами → «Ок» → по каждой теме план → «Ок» → текст |
| 1-е число, 10:00 | разбор за месяц: топ статей по трафику → эталоны агенту (знания «top-articles»), что выросло/просело, статьи агента до/после → агент предлагает правила, после «Ок» они вступают в силу |

В Telegram приходят только алерты (сломалось / починилось) и недельный отчёт.
Чьи статьи: редакция — профили из `SEO_OWN_AUTHORS` (dsgnersstudy), их статьи агент обновляет сам.
Статьи авторов — только SEO-поля (title, description, alt, разметка) и письмо автору с рекомендациями, текст не трогаем.

API сайта (`docs/site-api.md`, `SITE_API_URL` + `SITE_API_TOKEN`): после «Ок» статьи редакции публикуются сами
(картинки → текст → SEO-поля, только в профиле dsgnersstudy; с пометками [РАБОТА]/[ПРОВЕРИТЬ] — не публикуются), SEO-поля записываются на сайт сами,
письмо автору уходит от редакции на почту + обычное уведомление на сайте. Без API — пакет приходит владельцу.

Старые статьи: `/seo_bulk` — статьи с проблемами из недельного обхода (нет/плохой title, description, OG, alt)
оформляются дешёвым режимом (один запрос на статью, ~1 ¢): пробная партия 20 шт. «было → стало» → «Применить ко всем» или
«Переделать» с комментарием (станет правилом) → дальше по `SEO_BULK_PER_HOUR` в час, сразу на сайт через API
(без API — один CSV для импорта в конце). После одобрения новые статьи оформляются так же, сразу и без согласования.

Советы авторам: новая статья автора → за ~30 минут проверка (один запрос, ~1–2 ¢) → письмо автору с советами
тебе на «Ок» (после «Ок» — автору через API сайта). Хорошие статьи и короткие новости — без письма. `/seo_tips on|off`.
Расписание всех агентов — в ИИ-офисе, вкладка «Расписание».

Вордстат: выгрузку (CSV/XLSX) просто отправь боту файлом — фразы с частотами попадут в базу SEO-шника.
`SEO_TOPICS_PER_WEEK` — тем в неделю (5), `SEO_AUTO_PLANS=1` — не согласовывать планы статей из контент-плана
(согласуешь только список тем и готовые тексты). `/seo_plan` — собрать контент-план сейчас.

Статьи: `/article тема` → SEO-шник ищет конкурентов (поиск в интернете, ~1 ¢ за запрос), сдаёт **план** →
«Ок» → пишет текст и SEO-пакет. Работы авторов он не выдумывает: ставит метки `[РАБОТА: …]` для редактора.
Картинки: SEO-шник пишет ТЗ графическому дизайнеру (обложка 1200×630 + шаги/чек-листы и таблицы-сравнения,
шаблоны `article-cover`, `article-steps`, `article-compare`), получает файлы и вставляет их в текст на свои места.

Команды: `/seo_status`, `/seo_scan hourly|new|daily|weekly`, `/seo_page адрес` (проверка без ИИ), `/seo_fix адрес` (оформить статью).

Новая статья → SEO-агент присылает пакет: title, description, H1, лид для нейроответа, alt картинок, OpenGraph,
JSON-LD (Article + хлебные крошки), внутренние ссылки. Сам на сайт он не пишет: поля вставляются в редакторе.
Всё, что собирается из полей автоматически (разметка, OG, canonical), должен делать шаблон сайта — ТЗ в `docs/seo-site-template.md`.

Настройки в `.env`: `SEO_SITE`, `SEO_CONTENT_PATTERN` (какие адреса — статьи), `SEO_AUTO_OPTIMIZE_PER_DAY`,
`YANDEX_OAUTH_TOKEN` + `METRIKA_COUNTER_ID` (Вебмастер и Метрика), `INDEXNOW_KEY`. Без токенов работают все проверки, кроме Вебмастера и Метрики.

## Как дизайнер учится
«🔁 Переделать» → пишешь, что не так → это сохраняется в `data/feedback/designer.md`
и подмешивается во все следующие задачи. Удачные правила раз в неделю переносим
в `agents/designer/feedback.md` (в git). Посмотреть правила: `/rules` в боте.

## Установка на сервер (один раз, от root)
```bash
# 1. ключ доступа сервера к репозиторию
sudo -u agents mkdir -p /home/agents/.ssh
sudo -u agents ssh-keygen -t ed25519 -N "" -f /home/agents/.ssh/id_ed25519 -C dsgners-vps
cat /home/agents/.ssh/id_ed25519.pub
#    → GitHub: репо → Settings → Deploy keys → Add deploy key, вставить, Write не нужен

# 2. скачать код и установить
sudo -u agents GIT_SSH_COMMAND="ssh -o StrictHostKeyChecking=accept-new" \
  git clone git@github.com:EvgenyMalkov/dsgners-agents.git /home/agents/dsgners-agents
bash /home/agents/dsgners-agents/deploy/install.sh
```

## Обновление
Автоматически: сервер раз в минуту проверяет GitHub и сам обновляется (не во время задач).
Перед запуском новая версия проходит проверку (`core/selftest.py`) и проверку запуска; если что-то не так —
остаётся прежняя версия, в Telegram приходит сообщение. `/rollback` в боте — вернуть предыдущую версию.
Журнал: `tail /var/log/dsgners-autoupdate.log`. Вручную, если нужно срочно:
```bash
bash /home/agents/dsgners-agents/deploy/update.sh
```
Логи: `journalctl -u dsgners-bot -f`

## Добавить нового агента
Папка `agents/<имя>/` с `ROLE.md`, `checklist.md`, `feedback.md`, `tools.py` (TOOLS + handle), `skills/`; запись в `core/office.py` (AGENTS) и стол в `web/office.html`. Общие инструменты — `core/common_tools.py`.
