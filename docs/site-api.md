# ТЗ: API сайта dsgners.ru для ИИ-агентов

**Зачем.** SEO-агент пишет статьи редакции (профиль `dsgners_study`), готовит SEO-поля (title, description, подписи
к картинкам, разметку) и письма авторам с советами. Сейчас владелец вносит это руками. С этим API после его «Ок»
в Telegram всё уходит на сайт само.

**Новых разделов, страниц и настроек на сайте не нужно.** Только методы поверх того, что уже есть:
статьи, загрузка картинок, поля статьи, отправка писем и уведомления. Ограничения (не чаще одного письма в 30 дней по статье) и история
правок — на стороне агентов.

## Доступ
- Адрес, например `https://dsgners.ru/api/agents`.
- Заголовок `Authorization: Bearer <токен>`; токен — длинная случайная строка в конфиге сайта.
  Владелец вписывает её в `.env` агентов (`SITE_API_TOKEN`), адрес — в `SITE_API_URL`.
- Желательно: пускать только с IP сервера агентов (даст владелец).
- Ответы — JSON, ошибки — `{"error": "текст"}` с кодом 4xx/5xx.

## 1. Получить статью
`GET /article?url=<полный адрес статьи>`

```json
{
  "id": 12366,
  "author": "na_produkte",
  "seo": { "seo_title": "", "meta_description": "", "og_title": "", "og_description": "", "jsonld": "" },
  "images": [ {"src": "https://dsgners.ru/upload/…/1.jpg", "alt": ""} ]
}
```
`404`, если статьи нет. Почту автора не отдавать. Если каких-то SEO-полей у статьи сейчас нет — просто не включать их.

## 2. Записать SEO-поля
`PATCH /article/{id}/seo`

```json
{
  "seo_title": "…",
  "meta_description": "…",
  "og_title": "…",
  "og_description": "…",
  "jsonld": "{\"@context\":\"https://schema.org\", …}",
  "images": [ {"src": "https://dsgners.ru/upload/…/1.jpg", "alt": "…"} ]
}
```
- Все поля необязательные: что пришло — обновить, остальное не трогать.
- Если у статьи нет отдельных полей под SEO title / description / OG — выводить их в `<head>` статьи из того,
  что пришло (можно хранить в одном JSON-поле статьи). `jsonld` — в `<script type="application/ld+json">`.
- `images` — только `alt` у картинок этой статьи с таким `src`.
- Текст, заголовок статьи, обложку, автора — не менять.
- Ответ: `{"ok": true}`.

## 3. Письмо автору
`POST /author-message`

```json
{ "article_id": 12366, "subject": "Как вернуть читателей статье «…»", "text": "до 1500 знаков, простой текст" }
```
Сайт отправляет автору статьи **тем же механизмом, что уже есть**:
1. **Email** на почту автора из профиля: тема = `subject`, текст = `text`, в конце ссылка на статью.
   Отправитель — как у остальных писем сайта.
2. **Уведомление** на сайте (обычное, как другие уведомления): «Редакция dsgners: советы по вашей статье „<название>“ —
   письмо у вас на почте», ссылка — на саму статью.

Если у сайта нет одного из механизмов — сделать то, что есть, и вернуть это в ответе:
`{"ok": true, "email": true, "notification": true}`.

## 4. Загрузить картинку
`POST /upload` — `multipart/form-data`, поле `file` (PNG/JPG до 10 МБ). Тем же механизмом, что картинки в редакторе статей.
Ответ: `{"url": "https://dsgners.ru/upload/…/cover.png"}`.

## 5. Опубликовать статью редакции
`POST /article`

```json
{
  "author": "dsgners_study",
  "title": "Портфолио дизайнера без опыта: с чего начать",
  "html": "<p>…</p><h2>…</h2><p><img src=\"https://dsgners.ru/upload/…/steps.png\" alt=\"…\"></p><table>…</table>",
  "cover_url": "https://dsgners.ru/upload/…/cover.png",
  "tags": ["портфолио", "карьера"]
}
```
- **Публиковать можно только от профилей редакции** (сейчас только `dsgners_study`) — любой другой `author` → `403`.
- `html` — обычная разметка: `p, h2, h3, ul, ol, li, a, strong, em, blockquote, table, img`. Если редактор сайта хранит
  статьи в своём формате — сконвертировать из HTML так же, как при вставке в редактор.
- `tags` — если на сайте есть теги; иначе игнорировать.
- Статья публикуется сразу (владелец уже согласовал её в Telegram) и попадает в sitemap, как обычная.
- Ответ: `{"id": 12501, "url": "https://dsgners.ru/dsgners_study/12501-portfolio-dizaynera-bez-opyta"}`.

## 6. Обновить статью редакции
`PATCH /article/{id}` — те же поля `title`, `html`, `cover_url`, `tags`; что пришло — обновить.
**Только для статей профилей редакции** — статью любого другого автора → `403`. Адрес статьи не менять.
Ответ: `{"ok": true}`.

## Как проверить
1. `curl -H "Authorization: Bearer <токен>" "https://dsgners.ru/api/agents/article?url=<адрес статьи>"` — приходит JSON.
2. Без токена — `401`.
3. `PATCH` с новым `seo_title` → в коде страницы статьи новый `<title>`.
4. `POST /author-message` на тестовую статью своего аккаунта → пришло письмо и уведомление.
5. `POST /article` с `author` не из редакции → `403`; с `dsgners_study` → статья появилась на сайте.
6. В боте агентов: `/seo_fix <адрес статьи>` → «Ок» → бот отвечает «SEO-поля записаны на сайт»;
   `/article <тема>` → «Ок» на план → «Ок» на статью → бот присылает ссылку на опубликованную статью.
